# projects-status

Публичные статус-дашборды проектов. Дашборды живут в приватных репозиториях и
автоматически публикуются сюда на GitHub Pages — для сторон, которым важно
видеть состояние проекта, но не нужен доступ к самим репозиториям.

## Сайты

**Указатель всех дашбордов (лендинг):**
https://deepspacewombat.github.io/projects-status/

| Дашборд | Адрес | Источник | Обновление |
|---|---|---|---|
| [AM Legal Agent — доска задач](https://deepspacewombat.github.io/projects-status/probka-legal-agent-status/) | https://deepspacewombat.github.io/projects-status/probka-legal-agent-status/ | `personal-ai-os` (приватный) | автоматически, при пуше в источник |

Корень сайта — лендинг с карточками-ссылками; каждый дашборд — отдельный
подкаталог.

## Как работает публикация

- Источник каждого дашборда — приватный репозиторий. При изменении
  файла-источника workflow источника автоматически публикует копию в свой
  подкаталог этого репозитория. Локальная машина в публикации не участвует.
- В сообщении каждого коммита публикации зафиксирован SHA коммита источника:
  `status update from <источник>@<sha>`. По нему всегда можно установить,
  какая именно версия источника опубликована.
- Типичная задержка обновления — 1–3 минуты после пуша в источник.
- Если автоматическая публикация упала, сайт остаётся на последней успешной
  версии — данные не пропадают и не обнуляются.
- Файл-источник — единственный источник правды. Всё содержимое этого репо —
  зеркало, кроме корневого `index.html` (лендинг) и этого README, которые
  правятся вручную здесь.

## Структура репозитория

```
index.html                     # лендинг: карточки всех дашбордов (вручную)
assets/                        # картинки карточек лендинга (вручную)
  probka-legal-agent-status/   # папка-ассет карточки AM Legal Agent
README.md                      # этот файл
probka-legal-agent-status/     # дашборд AM Legal Agent (авто-публикация)
  index.html
```

Картинка на карточке лендинга выбирается случайно при каждой загрузке
страницы (без памяти о прошлом выборе). Список картинок не ведётся: скрипт
лендинга перечитывает папку карточки (`assets/<имя-карточки>/`) через
GitHub Contents API и выбирает случайный файл-изображение. Добавить картинку
в ротацию = положить файл в папку карточки; имя и количество не важны.
Без JS или при недоступности API показывается `src` по умолчанию из
`index.html`. Новый файл появляется на сайте после пуша (сам лендинг может
кэшироваться Pages до 10 минут).

## Для владельца: добавить новый дашборд

1. В приватном репо-источнике — workflow публикации (по образцу
   `publish-status.yml`) с `target-directory: '<имя-дашборда>'`.
   Подкаталог — никогда не корень: публикация дашборда затирает и обновляет
   только свой подкаталог, соседние дашборды и лендинг не трогает.
2. Здесь, в корневом `index.html` — карточка со ссылкой на новый адрес.
3. Первая публикация — вручную (Actions → Run workflow), дальше — автоматически.

## Безопасность

- Публикующий токен — fine-grained PAT с доступом только к этому репозиторию
  (Contents: Read and write). Компрометация токена не даёт доступа к репо-
  источникам и аккаунту.
- Ротация токена — каждые 90 дней.
- Перед публикацией источник проходит автоматическую проверку на секреты;
  запуск с подозрительными строками останавливается, сайт остаётся на прежней
  версии.
